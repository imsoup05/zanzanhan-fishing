## 2. 코어 루프 ★

한 사이클 약 10~20초.

```
캐스팅(물 탭) → 대기(1.6~4.2초) → 입질(등급 확정) → 릴링(타이밍 탭 N회) → 결과 카드 → 캐스팅
```

| 단계 | 플레이어 조작 | 게임 피드백 | 재미 지점 |
|---|---|---|---|
| 캐스팅 | 물 영역 아무 곳 탭 | 낚싯찌 포물선, 물튀김 효과음, 햅틱 | — |
| 대기 | 없음 | 찌가 떠 있음, 잔잔한 BGM | 기다림 자체가 톤 |
| 입질 | 없음 | "입질이 왔어요!" + 번개 아이콘, 효과음, 햅틱 | 놀람 |
| 릴링 | 세로 게이지의 흰 표시가 파란 존 안에 있을 때 화면 탭 | 히트/미스 효과음, 게이지 옆 물고기 아이콘이 등급 색으로 채워짐 | **긴장 + 등급 공개 연출** |
| 결과 | 카드 닫기 | 물고기 이름·크기·판매가, NEW! 배지, 성공/실패 멜로디 | 보상 |

**판정 규칙**
- 히트 필요 횟수: 등급별 최소값 + 랜덤 0~1. 미스 허용 3회(전설 2회). 히트마다 제한시간이 있고 초과 시 즉시 실패.
- 판정 오차는 게이지 속도에 비례(가장 빠를 때 양쪽 합 8%, 가장 느릴 때 15%). 느린 게이지는 관대하게, 빠른 게이지는 정밀하게.
- 등급별 난이도는 **곡선형**: 꽝·일반·희귀는 넉넉, 특급부터 조여지고, 전설만 진짜 벽.

| 등급 | 최소 히트 | 허용 미스 | 존 높이 | 제한시간 | 게이지 주기 | 실효 판정 창 |
|---|---|---|---|---|---|---|
| 꽝 | 2 | 3 | 34% | 4.0초 | 1.25초 | 0.61초 |
| 일반 | 2 | 3 | 28% | 3.8초 | 1.10초 | 0.45초 |
| 희귀 | 3 | 3 | 21% | 3.4초 | 0.95초 | 0.31초 |
| 특급 | 4 | 3 | 16% | 3.0초 | 0.80초 | 0.21초 |
| 전설 | 4 | 2 | 12% | 2.8초 | 0.65초 | 0.13초 |

**등급 공개 연출 (릴링 중)**: 입질 시점에 등급은 이미 정해졌지만 곧바로 알려주지 않는다. 히트마다 "창"이 열리고 창의 등급이 색으로 공개된다. 창의 등급은 내려가지 않고, 한 번에 최대 2등급만 오르며, 마지막 창은 항상 진짜 등급이다. 전설 색에 한 번이라도 닿으면 릴링 끝까지 금색 발광 유지(실제 전설이 아니어도 — 연출용 미끼). 게이지 속도는 **현재 표시 중인 등급**의 주기를 따른다.

**실패 조건과 손실**: 미스 초과 또는 시간 초과 → "놓쳤어요". 잃는 것은 소모한 미끼 1개뿐. 꽝은 성공해도 보관함에 안 들어감.

**[되짚기]** 코어 루프는 프로토타입 첫날에 나왔고 이후 거의 안 바뀌었다(제한시간 바를 뺐다가 다시 넣은 것 정도). 판정 오차를 속도 비례로 바꾼 것(v1.1)과 등급 공개 연출은 플레이해 보고 나온 조정이라 기획서로는 못 잡았을 영역이다. **이 장은 프로토타입이 옳았다.**

## 3. 메타 루프 (성장·목표) ★

### 성장 축 (3개)

| 축 | 단계 | 코어 루프에 미치는 영향 | 비용 재화 |
|---|---|---|---|
| **낚싯대 레벨** | 1~10 (등급마다 리셋, 보너스는 누적) | 존 높이 +0%→+30% (일반 0~8 / 희귀 8~18 / 특급 18~30) | 조개 |
| **낚싯대 등급** | 일반 → 희귀 → 특급 | 특급·전설 허용 미스 +1/+2, 특급 등급은 고등급 게이지 10% 감속, 저등급 릴링 자동 스킵 | 보석 (5개 / 12개), 레벨 10 필요 |
| **능력치 3종** | 각 0~5 | 근력: 제한시간 +3%p/단계. 행운: 꽝·일반 확률을 상위로 이동 6%p/단계. 정밀함: 게이지 속도 −4%p/단계 | 조개 |

낚싯대 등급의 효과는 **전설급 낚시에만 집중**한다 — 낮은 등급 물고기에는 보정이 없어서 등급업의 체감이 "전설을 잡을 수 있게 되는가"로 모인다.

### 콘텐츠 단위: 낚시터 3곳

낚시터는 **어떤 물고기가, 얼마에, 얼마나 어렵게** 낚이는지만 바꾼다. 등급 확률·미끼·낚싯대·능력치는 어디서나 같다.

| 낚시터 | 해금 조건 | 판매가 배율 | 릴링 가중 |
|---|---|---|---|
| 호수 | 기본 | ×1 | 없음 |
| 바다 | 호수 도감 12종 + 조개 5,000 | ×1.6 | 특급·전설 히트 +1, 제한시간 −10% |
| 심해 | 바다 도감 12종 + 희귀 낚싯대 + 조개 15,000 | ×2.5 | 모든 등급 히트 +1, 특급·전설 미스 −1, 존 −10%, 제한시간 −15% |

해금은 조건 충족 후 조개를 한 번 내면 되고, 이후 무료 이동. 낚시 중에는 이동 불가.

**[되짚기]** 낚시터 개념은 v1.2(출시 후)에 들어갔다. 처음부터 있었다면 어종을 서식지별로 한 번에 배치했을 텐데, 호수에 넣었던 계곡·강 어종 9종을 v2.0에서 빼고 심해아귀를 호수→심해로 옮겼다. 낚싯대 등급 보너스가 등급마다 0%→30%로 리셋되어 **등급업 직후 손해**였던 것도 v2.0에서 누적으로 고쳤다 — 성장 축을 표로 그려봤으면 바로 보였을 문제.

## 4. 경제 ★

### 4-1. 재화 목록

| 재화 | 역할 | 얻는 곳 | 쓰는 곳 | 제약 |
|---|---|---|---|---|
| **조개** (주 재화) | 대부분의 소비 | 물고기 판매(보관함 → 상점), 도전과제 보상 | 낚싯대 레벨업, 능력치 강화, 미끼 뽑기, 낚시터 해금, 수족관(수조·칸·장식, v2.1) | 상한 없음. 도전과제 보상 조개는 랭킹 점수(누적 판매)에 미포함 |
| **보석** (보조 재화) | 낚싯대 등급업 게이트 | 꽝 아닌 물고기 낚을 때 고정 6%, 도전과제 보상 | 낚싯대 등급업 (희귀 5 / 특급 12) | 단일 누적 잔액, 초과분 이월 |
| **미끼** (소모품 4종) | 등급 필터 | 뽑기, 도전과제 보상 | 캐스팅마다 1개 소모 | 기본 상태 "없음"(빈 바늘) |
| **물고기** (재고) | 조개로 바뀌기 전 상태 | 낚시 | 상점 판매, 수족관 전시(판매 포기, v2.1) | 판매가는 낚을 때 확정(배율 포함) |

### 4-2. 흐름표

```
낚시 ──▶ 물고기 ──판매──▶ 조개 ──┬──▶ 낚싯대 레벨 (총 62,300)
  │                              ├──▶ 능력치 3종 (총 15,000)
  │                              ├──▶ 미끼 뽑기 (150 / 1,500)
  │                              ├──▶ 낚시터 해금 (5,000 + 15,000)
  │                              └──▶ 수족관 수조·칸·장식 (v2.1, 약 324만)
  ├──6%──▶ 보석 ──▶ 낚싯대 등급업 (5 + 12)
  └──소모──▶ 미끼 ◀──뽑기──┘
도전과제 ──▶ 조개 9,720 · 보석 12 · 미끼 21 (전체 합계, 보조 수입)
```

조개의 유일한 주 수입은 판매다. 도전과제는 상징적 보상(쉬운 과제 30~50)으로 낮춰 "조개 수급은 낚시로"를 유지한다.

### 4-3. 목표 시간 곡선

곡선 모양: **초반 완만, 후반 급상승** (v2.0). 낚싯대 레벨 1~5는 완만(100·100·200·200·300), 6~10은 가파름(600·1,200·2,200·4,000). 능력치도 300·400·600·1,200·2,500.

| 마일스톤 | 필요 조개 | 비고 |
|---|---|---|
| 첫 강화 | 100 | 튜토리얼 첫 판매 직후 가능 |
| 일반 낚싯대 Lv10 | 8,900 | |
| 바다 해금 | 5,000 + 도감 12종 | |
| 희귀 낚싯대 Lv10 | +17,800 | |
| 심해 해금 | 15,000 + 희귀 낚싯대 + 바다 도감 12종 | |
| 특급 낚싯대 Lv10 | +35,600 | |
| 전부 | 조개 약 97,300 + 보석 17 | |

**[되짚기]** 시간당 수입 가정이 문서화되지 않았다. 가격표를 먼저 정하고(v0.1) 플레이해 보니 초반이 답답해서 보상을 크게 올렸다가(v1.1, 도전과제 합계 조개 25,450), 후반이 너무 빨리 끝나 다시 낮추고 낚싯대 비용을 34,600→62,300으로 올렸다(v2.0). "특급 낚싯대까지 N시간"을 먼저 정하고 역산했으면 한 번에 끝났을 작업. 전설 판매가도 8,000~15,000에서 2,500~5,000으로 내렸는데, 전설 한 마리가 특급 열 마리 값이라 수입이 전설 운에 매달리는 구조를 뒤늦게 발견한 것.

### 4-4. 확률표 (게임 내 고지값과 동일)

**등급 출현** (행운 0 기준): 꽝 10% · 일반 52% · 희귀 27% · 특급 10.5% · 전설 0.5%. 행운 5에서 7 · 36.4 · 32.02 · 23.71 · 0.87. 어느 단계에서도 일반 > 희귀 > 특급 > 전설 유지.

**미끼 필터**: 없음 = 전설 불가 / 일반 = 표 그대로 / 희귀·특급·전설 = 그 등급 이상만(걸러진 확률은 남은 등급에 비례 재분배).

**미끼 뽑기**: 일반 57.5% · 희귀 29.9% · 특급 11.6% · 전설 1%. 1뽑 150, 10뽑 1,500(특급 이상 1개 보정). 천장: 80뽑 누적 시 전설 확정.

**보석 드랍**: 꽝 제외 물고기당 6% 고정.

**판매가**: 등급별 구간 × 종 내 크기 비율 × 낚시터 배율. 구간은 겹치지 않음 (일반 8~45 / 희귀 60~220 / 특급 400~1,300 / 전설 2,500~5,000).

**[되짚기]** 재화 종류가 두 번 바뀌었다. 낚싯대 강화 재료가 등급별 2종이었다가 보석 1종으로 통합(v0.3.2, 스키마 4). 미끼는 소모품 → 일반 미끼 무한 → 다시 소모품 + 빈 바늘(v2.0, 스키마 12). 뽑기 "조개 환급 카드"도 넣었다가 뺐다. **재화 표를 처음에 확정했으면 스키마 변경 12회 중 최소 4회는 없었다.**

## 6. 화면 구조도

```
타이틀 (첫 터치 = 첫 캐스팅, 시작 버튼 없음)
 └─ 메인 (캔버스 배경 + HUD)
     ├─ 상단바: [낚시터 이름 ▸ 낚시터 팝업] [조개] [보석]  ······ 우측 비움(토스 닫기 버튼)
     ├─ 릴링 게이지 (왼쪽, 릴링 중만; 왼손 모드 시 오른쪽)
     ├─ 하단 탭 5개: 상점 | 보관함 | 미끼 | 도전과제 | 설정
     │    └─ 미끼 탭 → 탭바 위로 선택 휠
     ├─ 수족관 모드 (v2.1): 캔버스 = 수조, 수조 칩, 하단 바 교체(전시 | 꾸미기 | 낚시하러 가기)
     └─ 팝업(오버레이)
         ├─ 상점 (탭: 뽑기 / 판매 / 강화)
         │    └─ 뽑기 결과 (카드 5×2, 전부 열어야 닫힘)
         ├─ 보관함 (탭: 보관함 / 도감 → 낚시터 탭)
         ├─ 도전과제 (앱인토스: 탭 도전과제 / 랭킹)
         ├─ 낚시터 (카드 목록 → 상세 시트, 맨 아래 수족관 카드 → 입장)
         ├─ 설정 → 데이터 삭제 확인
         ├─ 결과 카드 → 보석 획득
         ├─ 재화 설명, 종 상세
         └─ 종료 확인
```

- 하단 탭 상한 **5개** — 미끼 탭이 정중앙에 오도록.
- 릴링 중에는 탭바가 숨고 화면 전체가 탭 입력을 받는다.
- 세로 고정, 안전영역은 SDK 인셋을 CSS 변수로.

**[되짚기]** 랭킹을 v1.1에서 하단 탭 6번째로 넣었다가 v2.0.1에서 도전과제 팝업의 탭으로 옮겼다. 탭 상한을 먼저 정했으면 처음부터 팝업 안에 넣었을 것.

## 7. 콘텐츠 목록

### 어종: 3 낚시터 × (일반 10 · 희귀 7 · 특급 4 · 전설 3) = 72종 + 꽝 9종

| 낚시터 | 일반 예 | 전설 3종 | 꽝 3종 |
|---|---|---|---|
| 호수 | 피라미·붕어·블루길… | 이무기 · 천년 잉어 · 수정 산천어 | 낡은 장화 · 찌그러진 깡통 · 물에 불은 나무토막 |
| 바다 | (README 참고) | 해룡 · 용궁 거북 · 폭풍 범고래 | 엉킨 그물 · 플라스틱 병 · 해초 뭉치 |
| 심해 | (README 참고) | 리바이어던 · 크라켄 · 별빛아귀 | 녹슨 닻 · 심해 돌덩이 · 유리 부표 |

각 종: id · 이름 · 크기 범위(cm) · 한 줄 설명 · SVG 아이콘. 등급 컨셉: 일반 = 흔한 실존 / 희귀 = 보기 힘든 실존 / 특급 = 현실에 불가능한 변종 / 전설 = 신화. 전설 0.5%는 그 낚시터의 3종이 나눠 가짐(마리당 약 0.17%).

### 아트

- 배경: 캔버스 2D 프로시저럴. 정적 층(능선·나무·방파제·바위)은 한 번 그려 캐시, 물결·빛·부유물만 매 프레임. 낚시터마다 `paintStatic / paintWater / paintAbove`.
- 아이콘: SVG 파일 (ui / result / shop / fish / app 폴더). 미끼·재료처럼 등급 색만 다른 것은 파일을 등급별로 분리.
- 폰트: Pretendard 서브셋.

### 사운드 (파일 없음, WebAudio 합성)

- 효과음: tap · cast · bite · hit · miss · success · fail · splash · coin · gem · gachaReveal(등급별 4종) · 마지막 히트 창 알림.
- BGM 3곡(낚시터별), 이동 시 1.5초 크로스페이드. 호수 장조 패드 / 바다 넓은 보이싱 + 아르페지오 / 심해 단조 9화음 + 오르골 + 종.
- 톤 규칙: 효과음은 짧고 조용하게(길거나 크면 피로). 초저음(49Hz 이하)·맥놀이 금지(이어폰·폰 스피커에서 거북).

### 문구

"~해요"체. 실패 문구는 손실을 강조하지 않는다("놓쳤어요..."). 확률·천장은 상점에 상시 표시.

### 마이그레이션 정책

스키마 정수 + 단계별 변환 함수 배열. 각 단계는 바뀐 필드만 건드리고 나머지는 통과. 경로를 모르는 데이터만 초기화.

**[되짚기]** 스키마 이력: 1 버전 필드 이름 → 2 미끼 → 3 천장 → 4 재료→보석 통합 → … → 10 도전과제 보상 소급 → 12 일반 미끼 소모품화. 이 중 시스템 **추가**(2, 3, 도전과제, 낚시터)는 기획이 있어도 생겼겠지만, **재설계**(4, 12)와 소급(10)은 재화·보상 구조를 먼저 정했으면 없었다.

## 9. 플랫폼 요구사항

| 항목 | 웹(PWA) | 원스토어(Capacitor) | 앱인토스 |
|---|---|---|---|
| 저장 | localStorage | localStorage | 토스 스토리지 (userKey 기반, 시작 시 hydration) |
| 햅틱 | navigator.vibrate 근사 | 동일 | 토스 SDK 햅틱 어휘 그대로 |
| 종료 | history.go(-2) | App.exitApp 네이티브 | SDK |
| 랭킹 | 없음 (UI 숨김) | 없음 | 게임센터, 누적 판매 조개 |
| 세로 고정 | manifest + orientation.lock | 네이티브 | 컨테이너 |
| 업데이트 | sw.js 배너 | — | 번들 배포 |

- `window.Platform` 하나가 경계. game.js는 `storage / haptic / lockPortrait / exit / hasLeaderboard / submitScore / openLeaderboard / ready`만 호출한다. 앱인토스 빌드는 `platform.js`만 교체(별도 저장소 `zanzanhan-fishing-ait`).
- 토스 SDK 없이도 전체 게임이 동작한다. 랭킹만 숨겨진다.
- 심의 대응: 확률·천장 상시 표시, 종료 확인창, 데이터 삭제는 3초 지연 버튼.
- 오프라인: sw.js 네트워크 우선 + 캐시 폴백으로 동작.

## 부록: 이 게임에서 얻은 교훈

1. **코어 루프는 프로토타입이 맞았다.** 릴링 감각·판정 오차·등급 공개 연출은 기획서로 못 잡는다.
2. **재화 종류와 성장 축 표는 처음에 확정해야 한다.** 스키마 12회 중 재설계 성격의 변경은 여기서 나왔다.
3. **가격보다 시간 곡선을 먼저.** 경제를 두 번 갈아엎은 원인.
4. **콘텐츠 단위(낚시터)를 초기에 결정하면 유닛(어종) 배치가 한 번에 끝난다.**
5. **화면 구조도에서 탭 상한을 정한다.** 랭킹 위치가 두 번 바뀐 원인.
6. **파일 구조는 시스템 목록이 나온 뒤에.** game.js 3,900줄 단일 클로저는 "처음엔 300줄"의 결과.
