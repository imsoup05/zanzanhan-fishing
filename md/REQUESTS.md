# 의뢰 게시판 — 기획서

작성: 2026-09-26 · 대상 버전: v2.1 · 상위 문서: [GDD.md](GDD.md)

코드: 생성·판정·문구 `src/requests-data.js`, 게시판 상태·화면 `src/game.js`의 `의뢰 게시판` 절, 마크업 `index.html`의 `#achievements-tab-requests`.

## 0. 왜 만드는가

- 출시 후 2주 콘솔 데이터(2026-09-14~26, 신규 51명): 1일 후 23.5%, 3일 후 5.4%, 7일 후 3.7%가 돌아왔다. 대부분 성장 곡선(1~2시간)이나 수족관에 닿기 전에 떠난다. 표본이 작아 추세로만 본다.
- 다음 날 다시 들어올 이유가 게임에 없다. 성장은 조개를 모으는 일 하나이고, 도전과제는 한 번 깨면 끝이다.
- 그래서 **매일 조금씩 새로 생기는 목표**를 둔다. 단, 잔잔함(재촉·손해 없음)은 지킨다.

### 설계 원칙

1. **기한도, 놓쳤을 때의 손해도 없다.** 하지 않은 의뢰는 그대로 남는다. 하루 안에 끝내야 하는 것은 없다.
2. **수입을 늘리지 않는다.** 보상에 조개가 없다. 수족관이라는 조개 소비처를 스스로 상쇄하지 않기 위해서다([AQUARIUM.md](AQUARIUM.md) 열린 질문 2).
3. **평소 낚시로 채워진다.** 따로 들어가서 할 일이 없다. 잡은 물고기가 조건에 맞으면 저절로 올라간다.

## 1. 결정 사항

| 항목 | 결정 |
|---|---|
| 위치 | 도전과제 팝업의 탭 `도전과제 \| 의뢰 \| 랭킹`. 하단 탭 5개 상한 유지 |
| 열림 | 튜토리얼과 시스템 소개가 끝난 뒤 |
| 칸 | 3칸 |
| 갱신 | 보상을 받은 칸은 비고, **다음 날(기기 날짜 기준)** 새 의뢰가 들어온다. 안 끝난 의뢰는 계속 남는다 |
| 바꾸기 | 하루 1번, 안 끝난 의뢰 하나를 다른 의뢰로 바꾼다 |
| 대상 낚시터 | 해금한 낚시터 중 무작위 |
| 알림 | 완료되면 "의뢰 완료" 토스트. 도전과제 탭 배지에 받을 수 있는 의뢰 수가 더해지고, 의뢰 탭에 빨간 점 |
| 진행 인정 | 연습 낚시를 뺀 모든 낚시. 저등급 자동 스킵으로 잡힌 물고기도 센다 |

## 2. 의뢰 종류와 보상

| 종류 | 생성 비율 | 내용 | 보상 |
|---|---|---|---|
| 어종 | 45% | 일반 어종 3마리 (70%) | 일반 미끼 3 |
| | | 희귀 어종 1마리 (30%) | 희귀 미끼 1 |
| 크기 | 30% | 일반 어종, 그 종 크기 범위의 상위 30% 이상 1마리 (70%) | 희귀 미끼 1 |
| | | 희귀 어종, 같은 기준 1마리 (30%) | 희귀 미끼 2 |
| 등급 | 25% | 희귀 이상 3마리 (60%) | 희귀 미끼 2 |
| | | 특급 이상 1마리 (40%) | 보석 1 + 특급 미끼 1 |

- 같은 의뢰(같은 종류·낚시터·어종)는 게시판에 두 번 나오지 않는다. 등급 의뢰는 낚시터와 관계없이 한 번에 하나만 나온다.
- 전설 어종·전설 미끼는 나오지 않는다. 전설 미끼는 뽑기 천장(80뽑)에만 둔다.
- 수치는 `REWARDS`와 `build()`(`src/requests-data.js`)에서만 고치면 된다.

### 경제 영향 (추정)

- 하루 최대 3건. 보상을 모두 조개로 환산하면(도전과제 트로피 기준 BAIT_VALUE: 희귀 150, 특급 500) 하루 수백 조개 규모다. 심해 풀강 시간당 수입(약 15만, 추정)에 비하면 무시할 만하고, 초반 유저에게는 뽑기 몇 번 값이다.
- 미끼는 높은 등급 물고기를 부르므로 간접적으로 수입이 조금 는다. 하루 3건 상한이라 크지 않다고 본다. 실측으로 확인이 필요하다.

## 3. 데이터·저장

세이브 스키마 13 → 14.

```
requests: {
  list: [ req | null, req | null, req | null ],   // null = 오늘 보상을 받은 칸
  refillDay: 'YYYY-MM-DD' | null,                 // 빈 칸을 마지막으로 채운 날. null이면 아직 열리지 않음
  rerollDay: 'YYYY-MM-DD' | null,                 // 바꾸기를 쓴 날
  claimedTotal: 0
}
req = { kind: 'species' | 'size' | 'tier', stage, speciesId?, tier, minSize?, count, progress, reward }
```

- 마이그레이션 13→14: 빈 `requests`만 추가. 튜토리얼을 마친 기존 유저는 다음 실행 때 3칸이 채워진다.
- 로드 때 `RequestsData.normalizeList()`가 지금 빌드에 없는 어종·낚시터의 의뢰를 빈 칸으로 바꾼다.
- 날짜가 바뀌었는지는 실행할 때, 튜토리얼이 끝날 때, 의뢰 탭을 열 때, 앱이 백그라운드에서 돌아올 때 확인한다.

## 4. 분석

- `request_claim` { kind, stage, total }: 보상을 받을 때.
- `game_open`에 `requests_claimed`(누적 보상 받은 수)를 더했다.
- 다음 확인할 것: 의뢰를 받은 유저와 안 받은 유저의 다음 날 재방문 차이, 어느 종류가 가장 많이 끝나는지, 바꾸기 사용 빈도.

## 5. 열린 질문

1. **보상 체감**: 미끼 보상이 초반 유저에게 충분히 매력적인지. 약하면 한정 장식(수족관 소품, v2.2)을 보상으로 넣는 방법이 있다.
2. **기기 날짜 조작**: 날짜를 바꾸면 의뢰를 더 받을 수 있다. 싱글 게임이고 보상이 작아 막지 않는다.
3. **완료 연출**: 지금은 토스트뿐이다. 결과 카드에 "의뢰 완료" 표시를 붙일지.
